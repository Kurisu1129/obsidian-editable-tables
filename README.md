# Editable Tables — Obsidian 插件

在 Obsidian 的 Live Preview 里把表格渲染成**可编辑网格**，并且能渲染 **Obsidian 原生拒绝渲染的、嵌套在列表项内的表格**；引用块（blockquote）整段渲染，**引用里的表格和正文一样可编辑**，列表项里内嵌的块也不再"贴在最左边"。**编辑写回的是 Markdown 管道语法**（只有合并单元格才用 HTML），并提供 Markdown 导出。

## 它解决什么

| Obsidian 原生 | 装上本插件后 |
|---|---|
| 列表项内缩进的表格**完全不渲染**，显示裸管道源码，且 `editor:table-*` 命令返回 `false` | 正常渲染为可编辑表格，增删行列后缩进与列表结构原样保留 |
| 顶层表格可渲染，但增删行列/合并等能力只存在于**无 UI 的命令**里 | 鼠标悬停即出现工具栏，点一下就操作 |
| 编辑表格后往往被整体改写成 HTML | **保持 GFM 管道语法**；只有合并单元格这类管道表达不了的结构才用 HTML |
| 无合并单元格 | 框选后合并，`colspan`/`rowspan` 落盘，**GitHub 也能正确渲染** |
| 引用块里的表格、代码块、标题、列表大多**停在源码态**，`>` 前缀和管道符直接露给你看 | 整段引用块渲染成真正的 `blockquote`，**里面的表格也是可编辑网格**；代码块有高亮，标题有层级 |
| 列表项里的表格 / 引用块 / 代码块**左边缘贴到编辑区最左边**，看不出"属于哪一条" | 三类块都按父项正文的实际列位对齐，一级、二级嵌套各自对齐各自的父项 |

## 用法

在 Live Preview 中把鼠标移到表格上，工具栏出现在表格右上角（在表格自己的盒子里，见「宿主约束」）：

```
↑行 ↓行 −行 │ ←列 →列 −列 │ 左 中 右 │ 合并 拆分 │ 转 MD │ 源码
```

- **单元格编辑**：直接点进单元格打字。`Enter` 提交，`Escape` 还原，失焦自动提交。
- **合并**：从一个单元格**拖拽**到另一个（矩形框选），或点一个单元格后按住 `Shift` 点另一个；再点「合并」。单选时「合并」按钮的悬浮提示会说明这两种手势。
- **转 MD**：只对 HTML 存储的表格出现。网格可以无损表示成管道语法时一键转回 Markdown；含合并单元格 / 无表头 / 多行内容时按钮禁用并说明原因。
- **源码**：展开 Markdown 源码，回到原生编辑方式。
- 所有操作都可 `Ctrl+Z` 撤销、`Ctrl+Y` 重做。

### 引用块

连续的 `>` 行在光标**不在其中**时整段渲染，和 Obsidian 自己的 callout 用同一套模型：

- 引用块里的表格、围栏代码块、标题、列表**全部渲染**，`>` 前缀不再显示；
- 引用里的**表格直接可编辑**：悬停出现工具栏，单元格可输入，增删行列/对齐/合并拆分都与正文一致；写回时每一行都保留原来的 `>` 前缀（列表里的引用是 `  > `，嵌套引用是 `> > `），并且只要没有合并单元格，写回的就是**管道语法**，引用与列表结构不会被破坏；
- 光标**移进去**就整段还原为源码，可以直接改；移出来重新渲染；
- 渲染结果里的**内链、嵌入可点击**（实测 `[[笔记]]` 正常跳转）；
- 引用块的**文字**仍是只读渲染 —— 渲染、滚动、切换文件都不会写盘；只有你实际编辑了里面的表格才会改写那几行。

> 引用里的表格需要像正文一样**前面留一个空引用行**（单独一行 `>`）才会被渲染成表格——这是 Markdown 本身的规则，Obsidian 自己的阅读视图也如此。没有空行时它只是一段普通文字，插件不会接管。

callout（`> [!note]`）仍然交给 Obsidian 原生渲染，见「已知边界」。

## 安装

### 手动安装

1. 构建（或从 release 下载 `main.js`、`manifest.json`、`styles.css`）：

```bash
npm install
npm run build
```

2. 把 `main.js`、`manifest.json`、`styles.css` 复制到 `<vault>/.obsidian/plugins/editable-tables/`。
3. 在 Obsidian「设置 → 第三方插件」中启用 **Editable Tables**。

### 开发调试

```bash
npm install
npm run build
./scripts/deploy.sh /path/to/your/vault    # 默认部署到 ./spike-vault
```

发布到社区列表后，也可以通过 BRAT 或「浏览」市场安装。发布流程见 [RELEASE.md](RELEASE.md)。

## 存储格式：优先 Markdown，合并时才用 HTML

表格被你**实际编辑**后按以下规则写回：

- **管道表格**：只要网格仍能无损表示成 GFM 管道语法（没有合并/跨行、有表头、单元格单行），就写回管道语法 —— 对齐用 `:---:`，单元格里的 `|` 转义为 `\|`。**文件始终保持 Markdown。**
- **合并 / 跨行**：管道语法无法表达，这张表改为 HTML `<table>` 存储。这是唯一会主动落盘 HTML 的情况。
- **已经是 HTML 的表格**：默认保持 HTML；工具栏的「转 MD」可以在可表示时把它转回管道语法。

```markdown
| 姓名 | 年龄 |
| :--- | ---: |
| 张三 | 28 |
```

只有发生「管道 → HTML」的降级时才会提示一次。

**代价**：HTML 单元格内**不再解析 Markdown 行内格式** —— `**粗体**` 会原样显示。这是 HTML 的格式约束，不是本插件能绕过的。管道表格没有这个问题：单元格内容就是 Markdown 源码。

**只写你碰过的表格**：打开、滚动、切换文件都不会写入磁盘。合并单元格以外的普通操作也不会主动遍历全库改写。

## 导出 Markdown

命令面板提供两个命令（只在当前是 Markdown 笔记时可用）：

- **复制当前笔记为 Markdown**：把可转换的 HTML 表格转成管道语法后复制到剪贴板；
- **导出当前笔记为 Markdown 文件**：同样转换后下载为 `<笔记名>.md`。

导出是**只读**的：不会修改原笔记，也不会产生任何 vault 写入。合并单元格等无法用管道表示的表格原样保留 HTML，完成提示里会报出转换/保留的数量。围栏代码块、front matter、callout 里的内容不动。

## 已知边界

- **仅桌面端**（`isDesktopOnly: true`）
- 单元格按构造为单行，不支持 MultiMarkdown 的多行单元格
- **单元格内的行内 Markdown 在编辑态显示为源码**：`**粗体**`、`[链接]()` 在可编辑网格里显示为字面文本；写回的文件本身是正确 Markdown，阅读视图与其它工具会正常渲染
- **无表头的 HTML 表格无法转管道**：管道语法必须有表头行；这类表只能保持 HTML，「转 MD」按钮会禁用
- **导出不改写 callout 内的表格**，也不处理引用里紧贴正文、渲染器本身就不认作表格的 HTML；这些内容原样保留
- **导出统一使用 LF 行尾**
- **无法解析**的输入（例如未闭合的 `<table>`）拒绝渲染并原样保留源码，不改写文件
- 工具栏出现在表格**所在行的右端**（悬停 / 聚焦时显示）。表格较宽时它会盖住表头右上角一小块；面板窄于约 380px 时它会自动收缩换行成两排，按钮仍然全部可点 —— 见下方"宿主约束"
- **引用块的文字不在渲染态直接编辑**：单击不切回源码；在文字上**拖拽**会高亮选区，`Ctrl/Cmd+C` 即可复制；**双击文字**才回到源码编辑，并且光标落在**你点的那一行**（段落 / 标题 / 列表项 / 代码块 / 嵌套引用都支持；渲染结构与源码对不上时保守回退到引用首行）。链接与嵌入在渲染态可单击打开。引用里的**表格**是例外——它是独立的可编辑岛，单击单元格即可输入，双击表格不会把引用切回源码
- **代码块不接管**：列表项里的围栏代码块仍由 Obsidian 原生渲染（高亮、语言标签、折叠都还在），插件只补一行缩进。换来的是原生能力零损失
- **callout 仍然不接管**（D6）：callout 里的表格是 Obsidian 原生的渲染结果，不可编辑；callout 里的引用块也不接管。原因见下方"callout 为什么后置"
- **空列表项**（单独一行 `-`，项内没有文本）宿主本身就把它当普通行渲染，插件同样不会为它下面的块加缩进
- **缩进代码块里的 `>` 行会被误判为引用块**：四空格缩进的代码块（非围栏）内容若以 `>` 开头，扫描器会把它当成引用。它是只读渲染，不会写盘；双击即回到源码。这是已知边界，围栏代码块不受影响
- **源码模式仍显示 widget**：与表格一致，本插件工作在 Live Preview 的编辑器里，切到纯源码模式时 Obsidian 仍会加载扩展。只读渲染不改文件
- **主题 / 字号在挂载后变化不会立刻重算缩进**：widget 的 `padding-left` 在创建时测量一次，切换主题后已挂载的引用块/表格要等重新渲染（滚动出视口再回来或编辑）才对齐。代码块的行装饰会随视口重建自动更新

## 与宿主行为对齐

本插件**会写回文件**，所以"比 Obsidian 多识别一点"不是宽容，而是破坏 —— 被多识别的那段文本会在你第一次操作时被改写成表格标记。因此解析规则全部以**实测原生行为**为准：

| 规则 | 直觉 | 实测（Obsidian 原生） |
|---|---|---|
| 列宽 | 取表头列数，超出截断 | 取**所有行的最大列数**，短行补空 |
| 续行归属 | 只要含 `\|` 就算表格行 | 续行的**管道形状**必须与**表头一致** |

第二条的实际意义：表头写作 `| a | b |` 时，紧随其后的段落 `Use \`x | y\` for a pipe.` **不属于该表格**，不会被并入、更不会被改写。

**永不触碰的区域**：YAML front matter、代码围栏内的内容、未闭合的 `<table>`。

裸 `---` 在单格语法下是合法的分隔行 —— 不加限制就会把 front matter 解析成表格，编辑一次即吃掉收尾的 `---`，使整篇笔记变成未闭合的 YAML。这条已用测试固定。

## 宿主约束：工具栏为什么在表格内部

Obsidian 强制裁剪所有非可编辑的块级 widget：

```css
.markdown-source-view.mod-cm6 .cm-content > [contenteditable="false"] {
  contain: paint !important;
}
```

于是 widget 内任何定位到自身边界之外的元素都会被裁掉 —— 一个悬浮在表格上方的工具栏会**看不见也点不到**。这条规则带 `!important`，是宿主的刻意保证（防止 widget 内容串到相邻行），不该用 `!important` 去对抗。

所以工具栏落在 widget 自己的盒子里。这也是 Obsidian 自己的表格控件的做法 —— 它的行列拖拽手柄就在单元格内部，而非块外。

工具栏按**右边缘**对齐到 widget 盒的右端（也就是编辑行的右端），而不是表格的右边缘。对窄表格来说这样更好：工具栏停在表格右侧的空白里，一点都不遮挡。代价是表格很宽（占满整行）时它会压住表头右上角。

**面板窄于约 380px 时**（工具栏本身就这么宽）它会收缩并换行成两排，全部按钮仍可点。此前它会向左溢出到 widget 盒外被裁掉 —— 实测 12 个按钮只剩 3 个能点，且没有任何滚动条提示。两排虽然会盖住表格更多，但至少每个按钮都能用。

## 列表项内嵌块怎么对齐

列表项里的块有三类，各自都有"左边缘贴到最左边"的问题，但成因不同：

| 块 | 成因 | 做法 |
|---|---|---|
| 本插件的表格 widget / 引用块 widget | 块级 widget 是 `.cm-content` 的直接子元素，**不是 `.cm-line` 的子元素**，继承不到任何缩进 | 测量父项正文的实际列位，给 widget 根节点设 `padding-left` |
| Obsidian 原生的围栏代码块 | Obsidian 给列表**行**加 `padding-left`，但列表项内的代码行拿不到 | 只加一行 `Decoration.line`，不改 DOM、不改渲染 |

**不抄 CSS 变量，抄实测像素**：取最近一个带列表标记的兄弟行，用 `Range` 盖住它第一个字形，读 `getBoundingClientRect().left`，再减去 widget / 内容区自身的左边缘。这样 Obsidian 换主题、改 `--indent-unit`、改字号，对齐都自动跟上 —— 硬编码 23px 之类的数字会在下一次主题更新时错位。

代码块的缩进用 `margin-left: Npx !important` 的行装饰。`!important` 在这里是**承重**的：Obsidian 把 `.cm-line` 的 `margin: 0` 写在 CSS 级联层里并带了 `!important`，不带 `!important` 的内联样式会输给它，计算值仍是 `0px`（实测）。这是插件**唯一**对宿主使用 `!important` 的地方，作用域仅限"列表项内代码块的那些行"，**从不**用来对抗 `contain: paint`。

测量点取**内容区左边缘**而不是行自身的矩形：行此刻可能已经带着上一次加的 `margin-left`，用它自己的矩形相减会得到 0，下一次重建就会把装饰丢掉。从内容区量是幂等的 —— 打字、滚动、来回切换文件后缩进都稳定。

## callout 为什么后置

callout（`> [!note]`）**不能**用同样的办法扩展。研究实测（F30）：Obsidian 把整个 callout 正文替换成一个 block widget，**正文里连 `.cm-line` 都不存在** —— 而 CM6 装饰只能作用在文档行上，伸不进已经被 replace 的区间内部。

唯一可行的路径是**整段接管 callout 并自己重造它的 DOM**：标题、图标、折叠交互、类型点击、嵌套 callout……还要先做一次"`Prec.highest` 能否压过 `cm-callout`"的验证。成本和风险都与本任务不是一个量级，因此拆成单独任务（D6）。

在那之前，callout 里的表格仍由 Obsidian 原生渲染（可看不可编辑），callout 里的引用块也不接管 —— 这是**已知缺口**，不是 bug。

```
│   ├── region.ts       Region 判别联合：table / quote，共用 from/to/indent/source
│   ├── field.ts        两个 StateField：区域扫描（仅文档变更时重算）+ 装饰
│   ├── writeback.ts    唯一的写盘点：单块区间替换（只接受表格）
│   ├── indent.ts       量父项正文列位，给 widget 补 padding-left
│   ├── codeIndent.ts   给列表项内的原生代码块补行装饰缩进（不改 DOM、不接管）
│   └── index.ts        Prec.highest 装配
└── widget/
    ├── tableEditor.ts  表格交互本体（工具栏、选区、单元格编辑、写回），正文与引用共用
    ├── tableWidget.ts  CM6 块级 widget 外壳（eq / ignoreEvent / 生命周期）
    └── quoteWidget.ts  引用块：MarkdownRenderer + 生命周期 + 内嵌表格升级 + 高度上报
```

**视觉与原生逐像素对齐**：widget 根节点带 Obsidian 自己的 `markdown-rendered` 类，直接复用 `.markdown-rendered table|td|th` 这套由 `--table-*` 变量驱动的规则。实测表格宽度、行高、内边距、边框、`min-width` 与原生完全一致。

## 技术要点

- **`Prec.highest` 是必需的**，不是修饰：Obsidian 原生也用自己的块级 widget 渲染顶层表格，必须靠优先级压过它。**引用块不需要** —— 纯引用块本来就没有原生 widget 去争这块区间。
- **`WidgetType.eq` 的语义因 widget 而异**：表格 widget 持有偏移量并依赖它写回，`eq` 必须同时比较偏移量与源码 —— 只比源码会让 CodeMirror 在文档上方发生改动后复用旧 DOM，而旧 DOM 的事件闭包仍持有过期偏移，导致替换错误区间、损坏文档。引用块 widget 从不持有偏移（点击时从 DOM 现算），所以 `eq` 只比源码与缩进，避免上方每次击键都重建并异步重渲染。
- **块级 widget 高度必须准确报告**，否则光标会落到偏移若干行的位置。宿主用 `display: block`（绝不用 `display: contents`）。引用块是**异步渲染**的（`MarkdownRenderer.render` 返回 Promise），所以渲染完成后要再 `requestMeasure()` 一次，并用 `ResizeObserver` 兜住后续尺寸变化。
- **`MarkdownRenderer` 是追加语义**：渲染前必须清空容器，否则每次重渲染都会把内容叠加一遍；它还需要一个 `Component` 承载生命周期，`destroy` 时 `unload()`，否则嵌入的事件处理器会泄漏。
- **引用块的文字选中用 CSS Custom Highlight，不是原生选区**：`.cm-content` 里 `contenteditable=false` 的 island 无法用鼠标原生起选（Chromium 把选区一直保持为折叠）；而把 `window.getSelection()` 设进去会被 Obsidian 映射回文档位置并重建 widget —— 拖拽途中节点就被换掉。所以 widget 自己按坐标命中字符、用 `CSS.highlights` 画选区，并在 `copy` 事件里写剪贴板。
- **行装饰缩进只能靠 `margin-left: Npx !important`**：`padding-left` 只推文字、背景盒不动；`position`/`transform` 会让盒子右侧溢出被 `contain: paint` 裁掉。
- **测量必须幂等**：从内容区左边缘量，不要从行自身矩形量 —— 行已经带着上次的 `margin-left` 时，后者会算出 0 并丢掉装饰。
- **引用块内的表格与正文共用同一个编辑器**：`MarkdownRenderer` 渲染完成后，插件把引用源码里（剥掉 `>` 链后）扫描到的表格与渲染出的 `<table>` **按顺序配对**，用 `TableEditor` 原地替换。配对只在两边数量一致、且每张表的行数/列宽都与解析结果相符时成立——嵌入笔记等异步内容可能引入额外表格，一旦对不上就整块保持只读，绝不猜范围。写回时用表格首行的完整前缀（`> `、`  > `、`> > `、`>   `）作为序列化器的缩进（管道或 HTML 都逐行复现）。
- **引用内表格的坐标每次写盘前重新解析**：引用块 widget 的 `eq` 刻意不比较偏移量（否则上方每次击键都要异步重渲染整段引用），所以内嵌编辑器不能持有"构造时"的绝对偏移。它在每次提交前用 `view.posAtDOM(quoteRoot, 0)` 取当前位置，加上相对偏移构造新的 `TableRegion`，再由 `commitGrid` 的 `source` 比对兜底。
- **双击定位复用"渲染块 ↔ 源码块"的顺序配对**：引用块渲染成一个外层 `<blockquote>`，其元素子节点与源码的顶层块（标题 / 段落 / 列表 / 代码 / 嵌套引用 / 表格）按顺序配对；列表再用直接 `<li>` 序号对应 `itemStarts`。两个数量只要有一个对不上，就回退到引用首行——和引用内表格的配对同一条保守原则：宁可定位不改善，不能定位错行。
- **虚拟化下"找不到父项"不等于"没有缩进"**：CM6 只渲染视口，父项列表行可能不在 DOM 里。widget 侧按缩进字符串缓存像素列，并在视口变化时重新测量（否则快速滚动后嵌套块会永久贴左）；代码行侧只有确定是顶层才清缓存，父项暂时不可见时保留上次的缩进。
- **写回格式由网格结构决定，不由偏好决定**：管道表格只要没有合并/跨行、有表头、单元格单行，就写回管道语法；合并才降级 HTML。`canSerializePipe` 保守拒绝反斜杠紧邻管道、raw HTML 内含管道等无法无歧义往返的输入 —— 宁可多一张 HTML 表，也不写坏内容。
- **导出复用同一套扫描与序列化**：`exportMarkdown` 是纯函数，命令只读 `editor.getValue()`，复制或下载，不写 vault；导出与日常编辑因此不会产生第二套格式规则。
