# PRD：引用块双击定位到所点行

## 背景

渲染态的引用块是一整段原子 widget。双击进入源码时，光标固定落在引用块开头（`view.posAtDOM(wrap, 0)`），用户还要手动移到想编辑的那一行。引用块越长，这个动作越烦。

本任务只改善**入口位置**，不改变"整段还原为源码"的模型（逐行就地编辑是另一个更高风险的方向，见讨论记录，不在本任务范围）。

## 需求

- **R1 定位到所点行**：双击渲染态引用块中的文字 → 整段引用进入源码（与现在一致），但光标落在被点击内容对应的**源码行**，而不是引用块第一行。
- **R2 支持常见块**：
  - 段落（含 lazy continuation 续行，多条源码行渲染成一个 `<p>` 时落在段落首行）；
  - ATX / Setext 标题；
  - 列表：点击第 N 个顶层列表项，落在该项的源码行；嵌套项落到其所属顶层项；
  - 围栏代码块（落在开围栏行）；
  - 嵌套引用（落在该段嵌套引用的首行）；
  - 表格 / HTML 块 / 分割线（落在块首行）。
- **R3 保守回退**：渲染出的顶层块数量与源码扫描出的块数量不一致、或点击位置不在引用正文块内时，**回退到现有行为**（引用块开头）。宁可定位不改善，也不能定位错行。
- **R4 不改变其它行为**：单击 / 拖拽选字复制、链接与嵌入点击、引用内表格编辑、双击表格不进源码、写盘路径都保持不变；本功能**零写入**。
- **R5 可离线单测**：投影、块扫描、配对都是纯函数，放在 `src/model/`。

## 验收标准

- [x] **AC40 列表项定位**：双击引用内第 3 个列表项的文字 → 引用进入源码（widget 数 0），`editor.getCursor().line` 等于该列表项在文档中的源码行号。
- [x] **AC41 段落定位**：双击引用内某个段落的文字 → 光标落在该段落的源码行（多行 lazy 段落落在首行）。
- [x] **AC42 保守回退**：渲染块数与源码块数不一致的引用（实现用混合 bullet 标记 `- 甲` / `* 乙`，渲染器拆成两个 `<ul>`，扫描器只算一个列表），双击文字仍能进入源码且不抛错；光标回退到引用首行。数量一致时按 R1 定位。
- [x] **AC43 无回归**：AC1–AC38、AC40–AC42 全部通过（沿用 AC33 汇总断言）。**实施记录**：AC33 的汇总循环已扩展到 AC40–AC42，AC43 的"无回归"语义合并进 AC33，不再单独编号。
- [x] **单元测试**：`projectQuoteLines` / `scanQuoteBlocks` / `resolveQuoteLine` 覆盖段落、lazy、标题、列表项、代码、嵌套引用、表格、数量不一致回退（`tests/quoteLineMap.test.ts`，18 例）。

## 约束

- 不引入新依赖。
- 不新增写盘路径；双击只 dispatch selection。
- 渲染态 DOM 结构若与预期不符（找不到外层 `<blockquote>`、块数不一致），必须回退而不是猜。
- 与既有交互验收（AC26 / AC32）兼容：双击第一行仍落在同一行。
