# 表格编辑写回 Markdown 与导出 md

## Goal

用户的目标是：**编辑器展示渲染层，实际修改的是 Markdown 文档**。当前实现在这一点上是反的——任何 pipe 表格只要被编辑过一次，就会被永久改写为 HTML `<table>`，源文件不再是 Markdown，单元格里的行内 Markdown 也变成字面文本。

本次要做到：

1. 表格在渲染态编辑后，**只要网格能无损表示成 GFM 管道表格，就写回管道语法**；
2. 只有合并单元格 / 跨行这类管道语法无法表达的结构才使用 HTML；
3. 已存在的 HTML 表格可以显式转回 Markdown；
4. 提供 Markdown 导出命令，导出的文档里可转换的表格是管道语法。

## Background

- 写回唯一入口是 `src/editor/writeback.ts` 的 `commitGrid`，目前无条件调用 `serializeHtmlTable`。
- `src/model/` 有 `parsePipe.ts`（GFM → grid）与 `serializeHtml.ts`（grid → HTML），**没有反向的管道序列化**。
- `TableGrid` 已保留 `hasHeader`、`colAlign`、单元格的 `text/raw/rowSpan/colSpan/covered`，信息足以生成管道表格。
- 引用块内表格与正文共用 `TableEditor` / `commitGrid`，`region.indent` 是每行必须复现的行首前缀（`> `、`  > `、`> > `、`>   `）。
- 现有验收 AC29–AC31 断言引用内 pipe 表格编辑后变成 `> <table>`；本次行为变更后它们必须改为断言 `> | … |`。

## Requirements

### R1 管道表格编辑后写回管道语法

- 当表格原始存储为 `pipe`，且编辑后的网格满足**可管道化条件**时，写回 GFM 管道表格，而不是 HTML：
  - 每个单元格 `covered === false`、`rowSpan === 1`、`colSpan === 1`；
  - `grid.hasHeader === true`（管道表格必须有表头行 + 分隔行）；
  - 每个单元格的内容（`raw ?? text`）是单行（不含 `\r` / `\n`）；
  - 内容里不存在"反斜杠紧跟管道符"的序列（`/\+\|/`），否则无法与转义规则无歧义地往返；
  - 来自 HTML 的 `raw` 内容不含 `|`（避免把 HTML 标签/属性里的管道转义坏）。
- 写回时：
  - 第一行是表头，第二行是分隔行，对齐从 `grid.colAlign` 映射为 `---` / `:---` / `:---:` / `---:`；
  - 单元格里的 `|` 转义为 `\|`；
  - 每一行（含第一行）都加 `region.indent` 前缀；
  - 列数取网格宽度，短行补空。
- 不满足条件时退回 HTML 存储（例如用户合并了单元格）。pipe → HTML 的首次降级仍复用既有的一次性提示，提示文案改为说明"合并单元格无法用管道语法表示"。

### R2 HTML 表格可显式转回 Markdown

- 表格工具栏新增「转 MD」动作，仅对当前存储为 HTML 的表格显示。
- 当网格满足 R1 的可管道化条件时按钮可用；点击后把该表格原地改写为管道语法，内容、对齐、表头保持不变。
- 不满足条件时按钮禁用，悬浮提示说明原因（合并单元格 / 无表头 / 多行单元格）。
- 转换仍只经 `commitGrid`，仍受 `source` 校验保护，可 `Ctrl+Z` 撤销。

### R3 Markdown 导出

- 新增两个命令（命令面板，仅在活动视图是 Markdown 笔记时可用）：
  1. **复制当前笔记为 Markdown**：把当前笔记内容中所有可转换的 HTML 表格转成管道语法，复制到剪贴板；
  2. **导出当前笔记为 Markdown 文件**：同样转换后，以 `<笔记名>.md` 下载。
- 转换范围：
  - 正文 / 列表项内的 HTML 表格；
  - 引用块内的 HTML 表格（保留 `> ` 等前缀）；
  - 围栏代码块、front matter、callout、懒续行表格一律不动。
- 导出是**只读操作**：绝不修改原笔记；不产生任何 vault 写入。
- 导出完成后用 Notice 报告转换了几张表、几张因不可表示而保持 HTML。
- 无法转换的表格原样保留 HTML，不丢内容。

### R4 单元格内容规范化

- 单元格粘贴/输入产生换行时，折叠为单个空格再参与写回，保证：
  - 管道序列化永远拿到单行内容；
  - HTML 序列化不会在 `<td>` 里写入裸换行。

### R5 数据安全

- 写回仍只经 `commitGrid`，且必须先通过 `region.source` 比对；不匹配即放弃。
- 只替换目标表格自身的行范围；表格之外的字节逐字节不变。
- 序列化器必须保守：拿不准就返回"不可管道化"，退回 HTML，绝不猜测。

## Acceptance Criteria

- [x] **AC34 管道表格编辑后仍是 Markdown**：真实点击 pipe 表格单元格 → 输入 → Enter 后，文件里该表格仍是 `| … |` 管道语法（无 `<table>`），修改后的文本落盘，分隔行保留原对齐，表格外字节逐字节不变；重新加载后仍渲染为可编辑表格。
- [x] **AC35 合并降级与转回**：在 pipe 表格上合并两个单元格 → 写回 HTML（含 `colspan`）；拆分后仍是 HTML；点击「转 MD」→ 重新写回管道语法，内容与对齐不丢；`Ctrl+Z` 可撤销。
- [x] **AC36 引用内表格写回 Markdown**：编辑引用块内的 pipe 表格后，源码仍是带 `> ` 前缀的管道行（无 `<table>`），引用结构不变；列表内引用 / 嵌套引用的前缀同样保留。
- [x] **AC37 复制为 Markdown**：拦截 `navigator.clipboard.writeText` 后执行命令，捕获文本中可转换的 HTML 表格已变成管道语法、不可转换的保持 HTML；原笔记磁盘内容不变。
- [x] **AC38 导出为 Markdown 文件**：拦截 anchor 的 `download` / `click` 后执行命令，文件名为 `<笔记名>.md`，blob 内容与 AC37 的导出文本一致；原笔记磁盘内容不变。
- [ ] **AC39 无回归**：AC1–AC33 全部通过（AC29–AC31 的断言按本次行为变更改为管道语法）。**实施记录**：AC33 的汇总断言已扩展为覆盖 AC34–AC38，AC39 的"无回归"语义合并进 AC33，不再单独编号。

## Constraints

- 不引入新依赖。
- 不新增第二写盘路径；导出命令只读。
- 管道序列化必须是纯函数，放在 `src/model/`，可离线单测。
- 与既有行为兼容：已存在的 HTML 表格不会被自动批量改写，只有在被编辑或显式「转 MD」时才可能变化。
- 单元格仍按构造为单行；不支持 MultiMarkdown 多行单元格。

## Out of Scope

- 引用块正文（非表格）的渲染态直接输入——仍是双击进源码，单独任务。
- callout 内的表格接管（D6 仍推迟）。
- 单元格内行内 Markdown 的渲染态显示（`**粗体**` 在格子里仍显示为源码）。
- 导出到用户指定的任意文件系统路径（使用浏览器下载；不做路径选择器）。
- 移动端。
