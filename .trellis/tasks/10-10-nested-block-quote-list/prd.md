# 引用块渲染与嵌套块缩进对齐

> 承接 `09-16-block-render-table-edit`（已归档）明确推迟的切片。
> 那个任务的 PRD 把「列表项内嵌非表格块」与「callout 内表格」写进了 Out of Scope。

## Goal

在「md 文件是唯一真相」的前提下，补两块：

1. **纯引用块内的块级内容不再退化成源码** —— 表格、代码块、列表、标题在引用块内正常渲染
2. **嵌套块的缩进从属关系可见** —— 嵌在列表项里的块（含本插件已交付的表格 widget）不再「外凸」到父项正文左侧

用户价值：引用块现在是个「半渲染」的黑洞 —— 把表格或代码块放进引用里，看到的是一堆管道符和反引号。

## Background

### 需求的真实来源（含对早先判断的两次修正）

用户最初的表述是「嵌套列表的渲染和换行极不友善，列表项和子列表项内只能填写文字，不支持表格等」，随后要求「继续做列表项内嵌代码块和引用块」。

**实测推翻了那条要求里的前提**：

| 判断 | 实测 |
|---|---|
| 列表项内**不支持代码块** | ❌ 有误 —— 围栏代码块**正常渲染**，有语法高亮、语言标签、折叠指示器（F24、F34） |
| 列表项内**不支持表格** | ✅ 属实 —— 上一个任务已解决 |
| 「引用块内嵌块」是美观问题 | ❌ 比这严重 —— 引用块内的块级内容**完全不渲染**（F22） |

所以真实缺口**不在列表项内的代码块渲染**（本来就正常），而在：

- **纯引用块**是块级渲染的黑洞（顶层即复现，与列表无关）
- 嵌套块的**缩进失真**（含本插件自己的表格 widget）
- ~~callout 内表格不可编辑~~ —— 研究后确认成本过高，**本轮不做**（见 D6）

### 已确认的技术事实

沿用上一个任务 F1–F21 的编号。

**本任务首轮实测（CDP，真实运行中的 Obsidian）**

| # | 事实 |
|---|---|
| **F22** | **纯引用块内的块级 Markdown 完全不渲染**。`> \| a \| b \|` → 管道源码；`> ## 标题` → `## 标题` 字面量；`> - x` → `- x`；`> \`\`\`js` 与 `> \`\`\`` → 字面反引号（被当作行内代码）；`>     indented code` → 不渲染为代码块。**顶层引用块即复现** |
| **F23** | **callout 内的表格能渲染**（`> [!note]` 后的管道表格 → 真实 `<table>`），但**不是本插件的 widget**（`.mdft-table`=0），因此不可编辑 |
| **F24** | **列表项内的围栏代码块正常渲染**：语法高亮 + 语言标签（`JavaScript`） |
| **F25** | **嵌套块缩进失真**（字形左边缘，CSS px）：父列表项正文 x=**400**；2 空格缩进的代码块内容 x=**392**（**比父项正文还靠左 8px**）；4 空格 x=409；2 空格缩进的引用内容 x=418。代码块**背景盒** 376→980（整行宽），无视列表缩进 |
| **F26** | `>` 之后的围栏被当作行内代码渲染 —— 反引号对用户可见。F22 的一个具体表现 |
| **F27** | **测量手法**：量嵌套缩进**不能**用 `.cm-line` 的 `getBoundingClientRect()`（恒为整行宽 376→980），必须用 `document.createRange()` 取目标子串字形盒。判断控件可否点击也不能只看尺寸非零，要对按钮中心做 `elementFromPoint` |

**本任务研究阶段实测（反查 `obsidian.asar` + 运行时）**

| # | 事实 |
|---|---|
| **F28** | Live Preview 的渲染由**逐行语法 prop + 一个装饰构造器 `StateField`** 决定。纯引用行只带 `HyperMD-quote` / `-1` / `-2` / `-lazy`，**不带** `HyperMD-codeblock-*` / `HyperMD-table-row` / `HyperMD-header` / `HyperMD-list-line-*`。缺这些 prop，构造器就不会为围栏代码块 / 表格 / 标题 / 列表造 widget → 全部退化为「带引用条的纯文本」。**没有任何 CSS 类或设置能打开它** |
| **F29** | **callout 是唯一例外**：行 prop 同时含 `HyperMD-callout` 且 `HyperMD-quote-1` 时，构造器才把区间起点 `G` 置位，最终整段 `replace({block:true})` 成 `cm-embed-block cm-callout`。纯引用块 `G` 恒为 `-1`，永远不进该分支 |
| **F30** | **callout 正文被整段替换成单个 widget，正文里没有 `.cm-line`**（DOM 实测）。CM6 装饰只能作用在文档行上，**伸不进已被 replace 的区间内部** → 要把本插件表格塞进 callout，只能**整段接管 callout 并自己重造它的 DOM**（标题、图标、可折叠、类型点击）。**这就是 D6 决定后置的原因** |
| **F31** | `MarkdownRenderer.render(app, md, el, sourcePath, component) → Promise<void>`，**非全局**（插件内 `require('obsidian')` 可取）。覆盖标题 / 表格 / 代码高亮 / 列表 / 内链 / 嵌入 / callout / 数学，**detached 元素也能渲染**。坑：① **追加语义**，重复渲染到同一 `el` 会**叠加**，必须清容器；② 不传 `Component` 会 `console.error` 且嵌入的事件处理器不回收（泄漏）；③ 异步 |
| **F32** | **阅读层引擎本身完全支持引用块内块级内容** —— `render('> \|a\|b\|\n>\|--\|--\|')` 输出 `<blockquote><table>`。退化的**只是 Live Preview 编辑器**，不是 markdown 引擎 |
| **F33** | **跨多行的 `Decoration.replace({block:true})` 有大量原生先例**：callout 整段、围栏代码块整段、表格。硬约束是**区间必须行对齐**（不能只覆盖一行的一部分）。本项目 `region.from/to` 已是行对齐 |
| **F34** | 原生列表内代码块的能力清单：语法高亮、语言标签（`.code-block-flair`）、折叠指示器。层级类 `HyperMD-list-line-N` **只在 `begin` 行上有，内部行没有** → 纯 CSS 算不出该补多少 padding，**「改宿主 CSS」这条路不可行** |

### 与上一任务的关系

- 上一任务的成果（表格接管、可编辑网格、HTML 写回、数据安全护栏）是本任务的基础设施，**不得回归**（R21）。
- 本任务的资产：`src/model/`（纯函数层）、`src/editor/field.ts`（区域扫描 + 装饰 + 快速路径）、`src/widget/tableWidget.ts`、`scripts/acceptance.mjs`（AC1–AC13）。

## Key Decisions

- **D6 callout 内表格 —— 本轮不做，后置为单独任务**（用户确认）
  研究（F30）推翻了规划时的假设：callout 正文被整段替换成单个 widget，**正文里没有 `.cm-line`**，CM6 装饰伸不进去，**无法只接管内层表格**。唯一路径是整段接管 callout 并**自己重造整套 callout DOM**（标题、图标、可折叠、类型点击），还要做「`Prec.highest` 压过 `cm-callout`」的 spike（未实测）。
  用户选择**后置**，本轮记下这个能力缺口即可。

- **D7 引用块整段接管 + `MarkdownRenderer` 渲染；代码块不接管**（用户确认，两次决策）
  - **引用块**：以「一个连续引用块」为一个 region，光标在外 → `Decoration.replace({block:true})` widget，widget 内用 `MarkdownRenderer.render` 渲染整段引用源码（F31/F32）。与原生 callout **完全同构**（F29 + 光标进出模型），且**纯引用块本来就没有原生 widget，不需要 `Prec.highest` 去压任何东西**。
  - **代码块**：**不接管**。实测它在列表项内原生工作得很好（F24/F34），接管等于用自研渲染替换一个正常工作的原生实现（语法高亮、语言标签、折叠全要重造），是净退化风险。它的唯一问题是 8px 缩进，改用 **CM6 行装饰带内联样式**精确补 padding（见 D8）。
  - **被否决的路径**：「改宿主 `.HyperMD-list-line-nobullet` 的 CSS」—— 已实测**不可行**（F34：层级类只在 `begin` 行上有），且属全局副作用。

- **D8 缩进修正分三种载体，各用各的手段**
  | 载体 | 手段 |
  |---|---|
  | 本插件的表格 widget | widget 根节点自己设 `padding-left`（它不在 `.cm-line` 里，拿不到层级类，必须自算） |
  | 本插件的引用块 widget | 同上 |
  | **原生**代码块 | **CM6 行装饰**（`Decoration.line` 带内联 `style`）补 `padding-left`，**不替换原生渲染器** |
  缩进量的来源见 `research/container-indent.md`：优先抄最近的 `.HyperMD-list-line-N` 兄弟节点的 computed `padding-left`（自动跟随主题/字号/标记宽度），退化方案是按 `region.indent` 换算。

- **D9 行装饰补缩进是〔必经门禁〕**
  D8 里「用 CM6 行装饰给原生代码块补 padding」是**唯一未经验证**的技术点：Obsidian 自己也用行装饰（`cm-activeLine`、`HyperMD-*` 背景），我方行装饰的内联 `style` 能否稳定生效、是否与其冲突、是否会因装饰重建抖动，**均未知**。
  **必须先用 spike 取得明确结论**：能稳定生效 → 按 D8 实施；不能 → 回退为「代码块缩进不修，记为已知限制」，**不得带病推进**。

## Requirements

- **R14 引用块内块级渲染**：纯引用块内的表格、代码块（围栏与缩进）、列表、标题在 Live Preview 中正常渲染，不再退化为源码。
- **R15 缩进从属可见**：嵌在列表项内的块（**含本插件接管的表格 widget、引用块 widget，以及原生代码块**），其可视左边缘**不得**位于父项正文左侧。
  **实现约束**：不得修改宿主 `.HyperMD-list-line-nobullet` 的全局 CSS（F34 已证不可行，且是全局副作用）。
- **R16 引用块接管范围**：引用块在**全场景**接管（顶层与列表内一视同仁）—— R14 要求引用块内块级内容渲染，而 Obsidian 把引用块整体当源码行渲染，收窄到「仅列表内」在技术上没有意义。**代码块则完全不接管**，不受本条约束。
- **R17 单源无损**（承 R1）：本任务引入的任何写入必须无损序列化回文本；未编辑的内容**逐字节不变**。
- **R18 只读即零写入**：引用块渲染是**只读**的。打开、滚动、切换文件期间**不得产生任何磁盘写入**（承 R7/AC9）。
- **R19 光标不偏移**（承 AC6）：新引入的 block widget 必须准确报告高度（渲染是异步的，需占位 + `ResizeObserver`），点击落点与源码位置一致。
- **R20 可撤销**（承 R9）：由本任务引入的所有写入操作进入撤销历史。
- **R21 不破坏既有能力**：上一个任务的 AC1–AC13 全部不得回归。
- **R22 不替换正常工作的原生实现**：不得为修复次要缺陷而接管已经工作正常的原生渲染（D7 对代码块的要求）。

## Acceptance Criteria

- [ ] **AC14 引用块内表格渲染**：含「顶层引用块内的管道表格」的 md，在 Live Preview 中渲染为 `<table>` DOM，不再是管道源码。
- [ ] **AC15 引用块内代码块渲染**：引用块内的围栏代码块（含语言标注）渲染为代码块，**字面围栏行不再出现**（F26 的观测形式）。
- [ ] **AC16 引用块内列表与标题渲染**：引用块内的 `- ` 列表与 `## ` 标题不再显示标记符源码。
- [ ] **AC17 缩进从属**：列表项内嵌的块（**表格 widget、原生代码块、引用块 widget 各一例，含二级嵌套**）的**可视左边缘不早于**父列表项正文左边缘（F27 的手法：Range 取字形盒比 x）。**是「不早于」而非「精确等于」** —— 精确对齐是加分项，非门禁。
  **回归意义**：当前已交付的表格 widget 在此项上**失败**（376 vs 409，外凸 33px），本条同时是既有缺陷的修复验收。
- [ ] **AC17b〔门禁〕行装饰补缩进可行**（D9）：对原生代码块施加 CM6 行装饰后，其可视左边缘右移到不早于父项正文；**且**该缩进在「初次打开、编辑外围文本后、切换文件再回来」三种时机下稳定，不抖动。
  **若此项不通过** → 按 D9 回退为「代码块缩进不修」，**不得带病推进**。
- [ ] **AC17c 代码块零接管**（R22）：顶层与列表内的原生代码块，其 DOM **仍由 Obsidian 渲染** —— 断言 `.mdft-*` 不出现在代码块上，且原生能力（语法高亮 `token`、语言标签 `.code-block-flair`）仍在。
- [ ] **AC18 引用块接管稳定性**：`Cursor` 在引用块外时渲染为 widget，光标进入后还原为源码；三种时机（初次打开、编辑外围文本后、切走再回来）均稳定。
- [ ] **AC19 只读零写入**：仅打开、滚动、切换文件，含引用块与嵌套块的笔记写入数为 0（R18）。
- [ ] **AC20 光标不偏移**：在引用块前后各插入文本行后，点击引用块内元素的落点与源码位置一致（R19，异步渲染的高度同步）。
- [ ] **AC21 无回归**：上一个任务的 AC1–AC13 全部仍然通过。
- [ ] **AC22 引用块内内容可编辑**：光标进入引用块区间后，整段还原为源码，可直接编辑；离开后重新渲染，**磁盘内容不被改写**。

## Out of Scope

- **callout 内表格可编辑**（D6）—— 需整段接管 callout 并重造其 DOM + `Prec.highest` spike，后置为单独任务
- **接管原生代码块**（D7/R22）—— 原生工作正常，不替换
- 引用块内的**嵌套引用块 / callout 内的引用块**等深层组合 —— 除非实现路径天然覆盖
- 引用块内的**嵌入语法**（`![[...]]`）—— 走 `MarkdownRenderer` 自然获得则保留，不为此专项投入
- 引用块**渲染态的内联编辑**（直接在渲染结果上改字）—— 编辑一律回到源码态（AC22）
- 列表项内嵌**表格**（上一任务已交付）
- 移动端；存量笔记的批量迁移
